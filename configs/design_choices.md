| 1 Ingest+Enhance | Turn raw scanned pages into a stable, reproducible corpus ready for layout/OCR, without discarding evidence a rural-practitioner user would need cited. | 1,107 page-images (bk1=662 test, bk2=445 train) from 2 public-domain DLI books; JP2→PNG conversion; 29 boundary pages (covers/scan-cards, not content) failed conversion and were dropped harmlessly. | None (rule-based ingest). Preprocess offers `passthrough` vs `classical` (deskew/denoise/binarize); no learned enhancement model — `enhance.enabled: false`. | `loader.load_pages` sorts/scopes pages by document; `preprocess.run` in `passthrough` mode + `autocontrast` only — measured mean CER 0.174 vs 0.213 for the aggressive classical pipeline on a 5-page probe. Enhancement stage exists but is OFF: our data speciality is code-switching, not degraded scans. | `Page(id, image_path, doc_id)` contract is the fixed hand-off to layout/OCR; the preprocessing cache is fingerprinted, so any config change auto-invalidates it. | Each preprocess toggle (deskew/denoise/autocontrast/sharpen/binarize) was tested against held-out CER before picking passthrough; `get_data.sh` is idempotent (skips books already converted). | CPU-only, no GPU needed; JP2→PNG conversion runs in parallel across cores. | Raw/interim data gitignored, re-fetchable via `scripts/get_data.sh`; `data/provenance.md` records licence, source, and per-book counts. |
| 2 Layout | Decide what region(s) of a page OCR should read, and in what order — without corrupting text on our single-column corpus. | Same 1,107 preprocessed pages; the layout-strategy decision was validated on the 30-page bk1 held-out set. | Tesseract 5 (`--psm 3`) used only to locate text — no separate trained layout/detection model. | Two modes implemented and A/B measured: **block segmentation** (Tesseract word-boxes grouped into heading/body blocks) vs **`whole_page`** (one full-page region per page). Held-out mean CER: block **0.483** vs whole-page **0.184** (n=30) — block segmentation caused catastrophic failures (CER up to 5.69) on ~9 pages via mis-segmentation, with no benefit on this single-column corpus. `layout.mode: whole_page` selected. | `layout.detect(pages, cfg) -> list[Region]` signature is unchanged regardless of mode (CI-enforced); mode is a config switch, not a pipeline fork, so block segmentation stays available and reversible (`layout.mode: blocks`). | A/B tested with a held-out-CER notebook harness comparing block-pipeline, raw full-page, and in-pipeline whole-page; this process caught a real regression (see OCR row) before it shipped. | `whole_page` mode also skips the extra Tesseract layout pass entirely (~1 Tesseract call/page instead of layout+OCR), so it is faster as well as more accurate. | Decision + evidence logged in this table and `reports/pipeline_diagram.md`; the trade-off (losing the heading/body region split originally planned for entry-aware chunking) is accepted and recovered at chunk time via remedy-marker detection instead. |
| 3 OCR | Convert page images into text accurate enough to support ≥0.95 groundedness with 100% citation, on Bangla + code-switched content Tesseract wasn't tuned for. | Same 30-page held-out set. Gold labels are currently **Qwen-VLM-generated, not yet human-verified** — a known risk since the spec calls for manual transcription; CER numbers below should be read as provisional until spot-checked by hand. | Tesseract 5 (`ben+eng`, `oem 1`) — the reproduced pretrained baseline (A2 §3 requirement). A Bangla-capable neural fallback (Surya / bn-TrOCR) for low-confidence pages is planned but not yet implemented (`ocr.fallback: ""`). | Whole-page single pass at `--psm 3`. Two bugs were found and fixed while measuring: (1) whole-page regions now OCR the **original** page image directly instead of a re-saved crop — the re-saved crop dropped scan DPI, causing PSM 3 to mis-segment sparse pages; (2) the Tesseract TSV parser now uses `csv.QUOTE_NONE` — a stray `"` in OCR'd text was otherwise read as a CSV quote character, silently swallowing following rows into one field and inflating CER 3–4× on 5 pages. | `Reader.transcribe_region` / `transcribe()` signatures and the `Chunk.ocr_conf` contract are unchanged; per-page mean word confidence still feeds the `conf_threshold: 0.60` abstain gate. | Measured end-to-end on the held-out set: final mean CER **0.184** (target ≤ 0.15 — not yet met; closing this gap is A2's open item, via preprocessing tuning or the neural fallback, not a layout/parsing change). OCR output is cached by a fingerprint of image + region + `cfg['ocr']`, so config edits auto-invalidate stale cache. | CPU-only (Tesseract); no GPU dependency for this stage. | The two bugs found (DPI loss on re-saved crops, TSV quote-swallowing) are this milestone's documented "worst failure" evidence (A2 §5); CER is tracked per page, not just as a corpus mean, so regressions on specific page types are visible. |
| 4 Index | Turn OCR text into retrievable units that keep a remedy's name/symptoms/potency/dose together, and preserve page-level citation for grounding. | OCR text per page (`text`, `page_ids`, `doc_id`) → indexable Chunks. A remedy-alias table normalizes Bangla/Latin spelling variants (e.g. ভিরেট্রাম / Veratrum → `veratrum_album`) via `normalization.remedy_aliases` in config. | `BAAI/bge-m3` embeddings (dim 1024) — multilingual, actually covers Bengali (chosen over an English-only default); FAISS **Flat** index (exact search). | `chunk.split`: NFC-normalize text, strip control characters, mark remedy-alias occurrences, then group **entry-aware** (a new chunk starts at a remedy marker) with a 512-token / 64-overlap fallback window (BGE-m3 tokenizer) for entries that exceed the limit. | `Chunk` contract (`id`, `doc_id`, `text`, `page_ids`, `score`) is the fixed hand-off into A3 retrieval and must not change. Vectors are L2-normalized before storage so FAISS inner-product search behaves as cosine similarity; `store.build` validates chunk/vector count and dimension before persisting. | `index.type` is hard-restricted to `faiss:flat` for A2 — appropriate at this corpus size (~1,100 pages; exact search is fast enough, so ANN is not needed yet). Dimension mismatches / empty-chunk inputs raise explicit errors rather than silently corrupting the index. | Embedding runs on GPU when available (`cuda`, fp16, batch_size 4) and falls back to CPU automatically. | Index persisted atomically under `data/interim/index/` (gitignored, rebuildable via `scripts/build_index.sh`); real index statistics (chunk count, size on disk) are recorded once the full-corpus build is run — **TODO: fill in after the next full build**, do not report estimated numbers. |
